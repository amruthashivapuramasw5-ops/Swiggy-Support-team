# Domain: Support


## How to run

First, install the required package:

```bash
pip install -r requirements.txt
```

Then run the files in the following order from the project folder:

```bash
python generate_data.py
python part1.py
python part2.py
python part3.py
python part4.py
```

`generate_data.py` creates the dataset in the `data` folder. After that, each part generates its corresponding result files inside the `outputs` folder.

The output obtained while generating the dataset was:

```text
800 10 170 7cb48ef89914049d76954530b6482e04
```

This means the dataset contains 800 records, 10 columns and 170 positive/escalated records.

## Part 3 findings

In Part 3, I performed PCA and clustering analysis.

The analysis was done using 800 samples and 7 features. PCA was used to reduce and understand the variation in the data.

The first two principal components together explain about 55.52% of the variation in the dataset.

For K-means clustering, the selected best value of K was 4. The clusters had different escalation rates, showing that the support records can be grouped into different types of segments.

## Model-choice memo

Different models have different advantages.

Decision tree methods are easier to understand because we can see which features and conditions are used for making a decision. This can be useful when trying to understand the reason behind ticket escalation.

K-nearest-neighbour can be useful for comparing a support record with similar records. Clustering can help in grouping similar types of support records.

AdaBoost and voting methods combine multiple decisions or models, which can help improve the overall prediction performance.

The MLP model can learn more complex relationships between the input features.

In this project, I feel that accuracy alone should not be the only factor for choosing a model. For a real support system, it is also important that the result can be understood and used by the support team. So, an interpretable model can also be useful even if another model gives slightly better performance.

## Limitations

1. The dataset used in this project is synthetic data created for the capstone project. It is not real customer or Swiggy support data.

2. The model results are based on the given train and test split. Results may change if a different split is used.

3. The number of positive/escalated records in the test data is limited, which can affect metrics such as precision, recall and F1-score.

4. Only a limited number of features are available in the dataset. Real support data may contain many other factors that affect ticket escalation.

5. This project was tested only using the given dataset. The models have not been tested in a real-world support environment.
